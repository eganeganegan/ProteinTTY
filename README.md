# ProteinTTY

ProteinTTY is an interactive C++20 molecular structure viewer for the terminal. It parses PDB and mmCIF files and runs
a small software 3D pipeline: camera transforms, perspective or orthographic projection, depth-tested atom discs and
bonds, fake lighting, and ANSI-colored ASCII, Unicode, or Braille output.

There are no runtime dependencies beyond a POSIX terminal. Linux and macOS are supported.

## Features

- Fixed-column `ATOM` and `HETATM` parsing, including occupancy-selected alternate conformers, insertion codes,
  B-factor, element, chains, and residues
- Tag-indexed mmCIF `_atom_site` parsing independent of column order, with quoted and multiline value support
- PDB `HELIX`/`SHEET` and mmCIF `_struct_conf`/`_struct_sheet_range` secondary-structure coloring
- Chain-local C-alpha geometry fallback for unannotated protein helices and sheets, without overriding deposited records
- Automatic format detection from `.pdb`, `.ent`, `.cif`, `.mmcif`, or file content
- Centered molecular coordinates, calculated bounds, and automatic fit-to-terminal scaling
- Perspective and orthographic cameras with yaw, pitch, roll, pan-ready state, and zoom
- Reusable off-screen framebuffer with per-cell z-buffering
- Depth fog, directional fake lighting, atom-size hints, and terminal aspect-ratio correction
- Unicode, portable ASCII, and depth-tested 2x4 subcell Braille rendering
- Element, chain, residue class, B-factor, and secondary-structure color modes
- Atom, backbone, C-alpha trace, ball-and-stick, and one-point-per-residue modes
- Spatially indexed covalent-radius bond inference restricted to nearby residues
- Full string chain identifiers for modern mmCIF assemblies
- Live metadata, residue selection, center-nearest atom inspection, local sequence display, and a help overlay
- Interactive `:` command console with history, quoted values, chaining, help, and query output
- Repeatable `--command` automation and reusable `.ptty` command scripts
- Validated `--pdb ID` downloads with an XDG-compatible local RCSB cache
- Autorotation, clean screensaver mode, resize handling, and plain-text snapshots
- RAII terminal restoration after normal exits and caught exceptions; signal-aware shutdown for `SIGINT` and `SIGTERM`

## Build

Requirements: CMake 3.20 or newer and a C++20 compiler.

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

Install for the current user without elevated permissions:

```sh
cmake --install build --prefix "$HOME/.local"
```

Ensure `$HOME/.local/bin` is on `PATH` (it already is on many systems):

```sh
export PATH="$HOME/.local/bin:$PATH"
```

Running `cmake --install build` without `--prefix` uses CMake's default `/usr/local` prefix. On systems where
`/usr/local` is owned by `root`, that command requires administrator access; the user-local command above avoids it.

## Usage

Launch the interactive viewer:

```sh
./build/ascii-protein examples/1crn.pdb
```

Select an initial presentation:

```sh
./build/ascii-protein examples/1crn.pdb --mode ca --color residue --projection ortho
./build/ascii-protein examples/1crn.cif --renderer braille --color secondary
./build/ascii-protein examples/1crn.pdb --mode ball-stick --color element --charset unicode
./build/ascii-protein examples/1ubq.pdb --renderer braille --mode ca --color secondary
./build/ascii-protein --pdb 4HHB --renderer braille
./build/ascii-protein --pdb 4HHB --format cif --renderer braille
./build/ascii-protein examples/1crn.pdb --spin
./build/ascii-protein examples/1crn.pdb --script examples/presentation.ptty
./build/ascii-protein examples/1crn.pdb --command "show cartoon; color secondary; set renderer braille"
```

Create deterministic output for files, scripts, or CI:

```sh
./build/ascii-protein examples/1crn.pdb --snapshot --no-color --width 110 --height 32
```

When standard input or output is not a TTY, ProteinTTY renders one frame and exits automatically.

## Command Console

Press `:` while viewing a structure, type a command, and press `Enter`. Use `Escape` to cancel, Backspace to edit,
Up/Down to recall command history, and Tab to complete commands, settings, values, and selection names. Multiple
commands can be separated with `;`; quoted arguments preserve spaces.

```text
show atoms|backbone|cartoon|sticks|residues
show <selection>
hide <selection>
select <name> <selection>
delete <name>|all
color element|chain|residue|bfactor|secondary
color <selection> default|black|red|green|yellow|blue|magenta|cyan|white
set projection perspective|orthographic
set renderer cells|braille
set charset ascii|unicode
set info|sequence on|off|toggle
set background default|black|red|green|yellow|blue|magenta|cyan|white
spin on|off|toggle
zoom 1.5
zoom <selection>
center <selection>
inspect <single-atom-selection>
rotate yaw|pitch|roll 15
reset
count atoms|residues|chains
count <selection>
list chains|selections
sequence [chain]
distance <atom-serial|single-atom-selection> <atom-serial|single-atom-selection>
angle <atom1> <atom2> <atom3>
dihedral <atom1> <atom2> <atom3> <atom4>
load <structure.pdb|structure.cif>
fetch <PDB-ID> [format pdb|cif]
save <snapshot.txt>
info
help [command]
quit
```

Selections can use `all`, `none`, `chain`, `resi`, `resn`, `name`, `element`, `serial`, `hetero`, and `solvent`.
Combine predicates with `and`, `or`, `not`, and parentheses. Residue ranges and alternatives use forms such as
`resi 10-24` and `resn ASP+GLU`; quote chain identifiers containing spaces.

Selections operate on atoms. A residue therefore selects all of its atoms, and residue numbers may repeat between
chains. Use `chain A and resi 10` to identify one residue unambiguously. `show <selection>` displays only matching
atoms; `show all` restores the complete structure.

```text
select active chain A and resi 10-24
select acidic resn ASP+GLU
hide solvent
color active cyan
center active
zoom active
inspect chain A and resi 14 and name CA
distance 1 2
```

Measurement operands are atom serials or named selections containing exactly one atom. Loading or fetching a new
structure clears selections and atom-specific colors, resets the camera, and safely rebuilds inferred bonds.

The same dispatcher powers automation. Query output is written separately from snapshot output, and script lines
beginning with `#` are comments:

```sh
ascii-protein examples/1crn.pdb --command "count atoms"
ascii-protein examples/1crn.pdb --script examples/presentation.ptty
```

## Architecture

- `geometry.hpp` and `camera.hpp`: vectors, matrices, rotations, and view state
- `pdb_parser.cpp` and `mmcif_parser.cpp`: fixed-column PDB and tag-indexed mmCIF ingestion
- `structure_loader.cpp` and `structure.cpp`: format dispatch, conformer selection, hierarchy, centering, and bounds
- `framebuffer.cpp`: Unicode cells, ANSI serialization, and software depth buffer
- `renderer.cpp`: projection, lines, atom discs, lighting, spatially indexed bonds, palettes, and panels
- `rcsb.cpp`: validated RCSB downloads and atomic local caching through `curl`
- `terminal.cpp`: POSIX raw mode, alternate-screen lifecycle, resizing, input polling, and arrow-key decoding
- `cli.cpp` and `main.cpp`: option parsing and the application loop
- `command.cpp`: shared command tokenization, dispatch, queries, scripts, and interactive-console behavior
- `selection.cpp`: boolean molecular selection parsing and atom-mask evaluation
- `secondary_assignment.cpp`: C-alpha geometry fallback for unannotated secondary structure

`coordinate_frame_source.hpp` defines the format-independent frame producer contract for future trajectory playback,
without coupling trajectory formats to rendering or terminal handling.

## Example Data

The repository includes three structures downloaded from the RCSB Protein Data Bank:

- [`examples/1crn.pdb`](examples/1crn.pdb): crambin, a compact 46-residue protein
- [`examples/1crn.cif`](examples/1crn.cif): the same crambin structure in mmCIF format
- [`examples/1ubq.pdb`](examples/1ubq.pdb): ubiquitin, useful for secondary-structure traces
- [`examples/1bna.pdb`](examples/1bna.pdb): the Drew-Dickerson DNA dodecamer

Fetch any other four-character entry directly:

```sh
./build/ascii-protein --pdb 1CRN
./build/ascii-protein --pdb 1CRN --format cif
```

Remote loading requires `curl`. Downloads are cached under `$XDG_CACHE_HOME/ascii-protein`, or
`$HOME/.cache/ascii-protein` when `XDG_CACHE_HOME` is unset.

## Limitations

- PDB and core macromolecular mmCIF categories are supported; BinaryCIF and trajectory formats are not.
- Bond inference is intentionally approximate and does not model bond order or exhaustive ligand chemistry.
- Geometry-inferred secondary structure is an approximate C-alpha trace classification, not a hydrogen-bond-based
  DSSP replacement; deposited PDB/mmCIF annotations remain authoritative when present.
- Terminal input is POSIX-specific; native Windows consoles are not currently supported.
- The coordinate-frame interface is present, but no trajectory file reader or playback UI is implemented yet.

## Performance

Bond candidates are found through a 3D spatial hash rather than an all-pairs scan. On the development Mac, parsing and
rendering the 772 KB `4HHB.cif` hemoglobin structure in ball-and-stick mode takes approximately 0.10 seconds. Exact
timings vary by compiler, hardware, and terminal dimensions.
